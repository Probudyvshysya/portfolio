# Локальный поиск по документам агротрейдера

Менеджер спрашивает обычными словами: «какой штраф за недогруз», «сходится ли удостоверение качества
со спецификацией». Система находит нужные пункты в договорах и регламентах и отвечает со ссылкой на пункт.
Работает целиком на одном компьютере, интернет не нужен. Договоры, цены и анализы партий
остаются внутри компании.

Документы в `docs/` выдуманы: договор поставки соевого жмыха, спецификация, удостоверение качества
и регламент приёмки сои на элеваторе. В них специально заложены расхождения, которые человек пропускает.

## Как устроено

1. **Нарезка.** Каждый документ режется по пунктам, и один пункт становится одним фрагментом.
   Поэтому ответ ссылается на конкретный пункт договора, а не на файл целиком.
2. **Поиск.** Модель `bge-m3` переводит пункты и вопрос в векторы, берутся пять ближайших пунктов.
   Эмбеддинги считаются на процессоре, вся видеопамять остаётся языковой модели.
3. **Ответ.** `qwen3:4b-instruct` отвечает только по найденным пунктам и ставит номер источника.
   Если подходящего условия нет, пишет «В документах этого нет» и ничего не выдумывает.
4. **Проверка.** `questions.json` содержит 8 контрольных вопросов с эталоном: какие документы должен
   найти поиск и какие факты обязаны попасть в ответ. Прогон пишет отчёт в `results/`.

Запуск через [Ollama](https://ollama.com), Python без внешних библиотек.

```bash
ollama pull bge-m3
ollama pull qwen3:4b-instruct-2507-q4_K_M
python rag.py "Какой штраф за недогруз?"
python rag.py --eval
```

## Результат на обычном домашнем ПК

GTX 1650 с 4 ГБ видеопамяти и 16 ГБ памяти. Модель целиком в видеокарту не влезает,
треть слоёв работает на процессоре. [Полный отчёт с ответами модели →](results/eval-2026-10-16.md)

| | |
|---|---|
| Поиск нашёл нужные документы | **7 из 8** |
| Ответ содержит все обязательные факты | **7 из 8** |
| Время ответа | медиана 2,7 с, максимум 11,5 с |
| Выдуманных ответов | **0** |

Что получилось:
- **Поймала расхождение, которое пропустила лаборатория.** В удостоверении стоит «партия соответствует»,
  но протеин 41,2 % ниже базиса 42,0 %, а влажность 10,4 % выше нормы 10,0 %. Модель вывела оба
  расхождения построчно.
- **Посчитала скидку по договору:** протеин ниже базиса на 0,8 %, скидка 1,5 % за каждый процент,
  итого 1,2 % к цене.
- **Не повелась на ловушку.** На вопрос о штрафе за повреждение вагона ответила, что в документах
  этого нет, хотя рядом стоит пункт о простое вагонов.

Что не получилось:
- **Вопрос сразу по трём документам.** «Есть ли недогруз и положен ли штраф» требует веса из удостоверения
  (952,6 т), количества из спецификации (1 000 т) и допуска ±5 % из договора. Поиск принёс два документа
  из трёх, и модель честно ответила «в документах этого нет». Правильный ответ такой: нижняя граница
  950 т, недогруз в пределах допуска, штрафа нет.

## Что из этого следует для реальной работы

- **Арифметику и сверку цифр должен делать код.** Модель хорошо находит пункт и объясняет его,
  а сравнение веса с допуском надёжнее посчитать программой по извлечённым числам.
- **Вопросы по нескольким документам** требуют поиска по связке «договор + спецификация + партия»,
  а не по пяти ближайшим кускам. Следующий шаг: подтягивать документы одной сделки целиком.
- **Слабой видеокарты хватает для пилота.** Чтобы с системой одновременно работал отдел, нужен сервер
  с видеокартой от 16 ГБ и vLLM вместо Ollama.
- **Модель выбирать по замеру.** Сначала стояла `qwen3:4b`, и она «рассуждала вслух» по 700 слов
  на каждый вопрос, ответ занимал до трёх минут. Версия instruct даёт тот же ответ за секунды.

```bash
python -m pytest -q   # 6 тестов без Ollama: нарезка, сходство, сверка с эталоном
```
