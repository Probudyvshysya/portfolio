# Ревизор

Журнал решений (`journal.jsonl`) только дописывается: решение, причина, прогноз, а потом — исход.
Ревизор раз в месяц сводит, где прогноз систематически ошибается и какие отказы оказались зря.

## Шаги

1. `python -m dva review <журнал>`.
2. **Решения без исхода** — первым делом. Исход мог уже выйти; найти его и дописать через
   `Journal.outcome(id, outcome, actual)`, иначе ревизия считает по неполным данным.
3. **Смещение по сегменту.** Если средняя ошибка прогноза одного знака в ≥ 2 решениях подряд —
   это не случайность. Сформулировать предложение: какой порог и на сколько сдвинуть.
4. **Пропущено зря.** Для каждого `skipped_wrong` — какое правило отсева сработало и почему ошиблось.

## Чего ревизор не делает

- Не меняет пороги и правила сам. Пишет предложение, вносит его человек.
- Не переписывает записи журнала: исправление — это новая строка, старая остаётся.

## Формат

```
Без исхода: …
Сегмент «…»: n прогнозов, смещение +x → предложение: …
Пропущено зря: … → какое правило пересмотреть
```
